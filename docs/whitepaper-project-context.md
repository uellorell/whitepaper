# Whitepaper – Understanding Gen Z
## Project Context & Design Handoff

This document contains the current approved product, UX, and visual direction for the “Understanding Gen Z” Whitepaper landing page.

Use this document as the baseline before making future UX/UI changes.

This is documentation of the CURRENT direction.

It is not an instruction to redesign the page.

---

## 1. Project Overview

**Project Name**  
Whitepaper – Understanding Gen Z

**Company / Brand**  
Kompas.com / Research & Analytics KG Media

**Product Type**  
Responsive landing page for a paid digital research report / whitepaper.

**Business Objective**  
Sell a source of insight about Indonesian Gen Z based on findings synthesized from four research studies.

The report covers:

- Identity
- Culture
- Music
- Financial behavior

---

## 2. Main User Journey

The landing page is designed to move users through:

Unaware of the report  
→ Understand what it is  
→ Understand its value  
→ Become interested in the insights  
→ See the actual product  
→ Trust the research  
→ Understand its professional relevance  
→ Evaluate the purchase value  
→ Resolve remaining questions  
→ Purchase

## 4. Approved Landing Page Structure

The landing page currently uses 10 core narrative sections:

1. Hero
2. Why This Matters
3. Four Sides of Gen Z
4. Key Insight Teasers
5. Inside the Report
6. Behind the Research
7. Who Is This For
8. What You Get + Price

This is the current approved information architecture.

Do not change the structure without a clear product or UX reason.

## 12. Hero Visual

The Hero visual originally comes from a PDF source.

The PDF is only a source asset.

It should not be displayed as an embedded PDF viewer.

Current source visual frame:

**1280 × 800 px**

Aspect ratio:

**8:5**

Desktop uses the visual in a large immersive composition.

Avoid destroying important image composition through uncontrolled cropping or distortion.

## 13. Hero as Visual Source of Truth

The current Hero is the primary visual reference for the Whitepaper landing page.

The rest of the page may relate to it through:

- Color
- Typography rhythm
- Negative space
- Character treatment
- Image treatment
- Editorial composition
- Visual density
- Section transitions

The sections should not literally duplicate the Hero.

Principle:

**Hero establishes the language  
→ middle sections develop it  
→ Final CTA echoes it**

---

## 14. Character System

The Hero contains character/illustration elements that are part of the Understanding Gen Z identity.

The same approved character style may appear selectively throughout the page.

Current direction:

### Hero
Strongest character presence.

### Why This Matters
Supporting character.

### Key Insight Teasers
Selected character integration and strongest character presence after Hero.

### Who Is This For
Light / optional character support.

### Final CTA
Character returns as a visual echo of the Hero.

Characters generally do not need to appear in:

- Inside the Report
- Behind the Research
- FAQ

Those sections should remain more product-, evidence-, or information-focused.

Characters should always match the approved Hero visual style.

Do not introduce an unrelated illustration style.

## 16. Card & Container Philosophy

Avoid building the page as:

Card  
→ Card  
→ Card  
→ Card

Use hierarchy through:

- Typography
- Whitespace
- Imagery
- Dividers
- Background changes
- Composition

Avoid excessive:

- Rounded containers
- Nested cards
- Shadows
- Pills
- Gradients
- Glassmorphism
- Decorative blobs

---

## 17. Responsive Principles

### Desktop

More expressive and editorial.

Use large imagery, whitespace, and stronger compositions where appropriate.

### Tablet

Simplify complex layouts progressively.

Do not force desktop compositions into narrow spaces.

### Mobile

Do not mechanically stack the desktop design.

Prioritize:

- Readability
- Product understanding
- Clear CTA
- Appropriate image scale
- Simple interaction

Recommended horizontal padding:

16–20px

Recommended interactive target:

approximately 44px minimum where practical.

---

## 18. Accessibility

Maintain reasonable WCAG AA quality.

Important considerations:

- One semantic H1
- Logical heading hierarchy
- Sufficient contrast
- Keyboard accessibility
- Visible focus states
- Accessible FAQ accordion
- Accessible report carousel controls
- Appropriate image alt text
- Important content must not rely entirely on imagery or color
